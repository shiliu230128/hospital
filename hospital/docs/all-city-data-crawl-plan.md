# 全城市数据抓取写入规划

## 目标

覆盖北京、上海、深圳、杭州四个城市的医院挂号入口、微信入口、公开排班和可用性审计。页面可以展示可信 L0/L1 数据；对实时号源只做合规探测和风险标注，不伪造可挂状态。

## 数据分级

- L0：医院基础信息、官网、权威公开入口。
- L1：公开出诊/排班，包含医院、科室、医生、日期或星期、时段。
- L2：科室或日期级弱可约线索。
- L3：医生、日期、时段级当前可挂状态，需要稳定合规接口。
- L4：剩余号源数量或订单级校验，需要授权接口。

## 抓取范围

- 北京：保留现有 3 家 L1 样本，继续发现其它医院官网排班页。
- 上海：从 33 家目标医院官网发现出诊、专家排班、门诊安排页面。
- 深圳：从 23 家目标医院官网发现专家出诊、门诊排班、互联网医院入口。
- 杭州：从 18 家目标医院官网发现门诊排班、专家介绍、预约入口。

## 执行阶段

1. Registry 审计：解析四城医院清单，确认每家医院有官网或权威来源。
2. 官网可达性探测：低频请求官网首页，记录 HTTP 状态、耗时和文本信号。
3. 排班源发现：在官网首页和一跳页面中查找“出诊、排班、门诊、专家、预约”等链接。
4. 结构化解析：只把日期/星期、科室、医生、时段同时具备的表格或列表写成 L1。
5. 微信入口发现：完整模式抓取并解码官网二维码，候选先入报告，正式入口需人工核验或明确来源。
6. 前端写入：生成 `frontend-prototype/all-city-schedule-data.js`，由页面按城市加载。
7. 全链路抽测：校验数据文件、二维码引用、城市切换、医院详情和排班表渲染。

## 准确性规则

- 不从非医院官网域名自动晋升二维码。
- 不把入口页、新闻页、医生介绍页误标为排班。
- 不展示“实时余号”“当前可挂”或“剩余号源”，除非数据源达到 L3/L4。
- 每条 L1 记录必须保留 `sourceUrl` 和 `notes`。
- 抽测必须覆盖每个城市至少 3 家医院；有排班记录的城市需抽测 3 条记录。

## 输出物

- `data-access-research/all-city-crawl-report.json`
- `frontend-prototype/all-city-schedule-data.js`
- `frontend-prototype/generated/latest-report.js`
- 抽测结果写入报告中的 `endToEndChecks`

## 当前预期风险

- 医院官网结构不统一，需要逐步补 source-specific parser。
- 真实号源常在登录、App、微信小程序或验证码后，公开网页只能达到 L0/L1。
- 部分官网会限制访问、跳转或关闭历史页面，需要报告而不是强行绕过。
